# Cleanup handoff regression

## Observed failure

A copied monitor brief described a large project area but named specific paths mainly for recent growers and stale temporary data. The receiving agent refreshed metrics and discovered Git registrations, then offered a small synthetic-test cleanup batch. The user had to request wider coverage and explicit inspection of older worktrees and sibling project folders.

The expanded investigation found a much larger dependency-only batch across inactive, merge-proven worktrees. It also preserved older checkouts with open PRs, recent filesystem changes, ignored operational evidence, or insufficient merge proof. The initial shortlist was safe but insufficient for the requested audit. Moving the approved batch to Trash did not reclaim space.

The cleanup trace and its improvement handoff both identify execution failure: the local audit skill already required discovery and sibling coverage. Repeating that instruction alone would not fix the report's narrow path selection or make missing coverage visible. Private traces and exact inventories remain local; they are not published with this case study.

## Design correction

Reusable guidance describes discovery patterns and verifiable completion criteria. Concrete target paths come from the current report or fresh filesystem discovery; machine-specific folder names, approval lists and restore commands belong in private run evidence. The public case study and investigation procedure contain no workstation-specific cleanup targets.

- Share one investigation plan between HTML and copied prompt. Select large measured branches independently of growth; show shallow branches without counting their children twice. Keep old/unknown measurements explicit.
- Include every configured root and say explicitly that monitor coverage is narrower than a workstation audit. Stable large areas must not disappear behind a top-growers list.
- Embed structured evidence in an inert, folded JSON textarea. Retain all report folder rows and real parent paths for virtual groups. Agents can parse evidence without dumping CSS/JavaScript.
- Require a coverage artifact before a final proposal: enumerate direct project siblings, discover and reconcile Git roots/registrations, classify every material location, compare enumerated and classified counts, and identify gaps. Distinguish working checkouts from installed tools, test fixtures, archives, Trash and missing registrations.
- Inspect dependency-only candidates separately while protecting ignored reports, configuration, databases and unfinished work. Fresh exact merge/activity proof is required; whole-worktree removal additionally needs the 14-day commit and filesystem window. Unknown dates never qualify.
- Tie recommendations to the reserve shortfall, explain limited safe candidates, and separate allocated accounting from unique APFS reclaim. Inspect existing prevention and actual invocation coverage before proposing more tooling.

## Verification and limits

Synthetic workstation regressions include a stable large project family next to a small growing fixture, more than six configured roots, nested paths, unknown/zero measurements, virtual groups and malicious metadata. Browser checks exercise the visible starting points, evidence filtering and copied prompt. The five-part report order and folded appendix remain intact.

The monitor does not execute an audit, prove that a worktree is disposable, enforce an external agent's compliance, or perform cleanup. The coverage checklist makes the required result testable by the receiving agent; it is not a claim that the monitor has already reconciled the workstation. No new background full-disk scan or cleanup permission is introduced.
